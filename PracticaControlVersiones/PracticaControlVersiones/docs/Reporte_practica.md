# Reporte de práctica: control de versiones

## Objetivo
Aprender a organizar los cambios de una aplicación mediante Git y GitHub, usando ramas y colaboraciones.

## Descripción del proyecto
Se preparó una aplicación sencilla con una pantalla de bienvenida y un botón de inicio. El proyecto permite practicar cambios sin perder la versión principal.

## Procedimiento
**Creación de ramas:** se trabaja en una rama independiente llamada `diseno` para cambiar el color de la pantalla.

**Fusión:** los cambios de `diseno` se integran a `main` mediante `git merge`.

**Eliminación:** una vez fusionada, la rama se elimina con `git branch -d`.

**Permisos:** el dueño del repositorio invita colaboradores desde la configuración de GitHub.

**Conflictos:** se comparan cambios incompatibles en una misma línea y se corrige manualmente el archivo antes de completar la fusión.

**Contribuciones:** los compañeros pueden proponer cambios mediante Pull Requests, que se revisan antes de fusionar.

## Evidencias pendientes
Insertar capturas reales de la terminal y GitHub después de realizar las operaciones.

## Conclusión (adaptar después de hacer la práctica)
Git ayuda a conservar el historial de cambios y permite trabajar con diferentes versiones de un proyecto. GitHub facilita la colaboración y la revisión de aportaciones.
